# Requirements

A small school API: students, courses, and enrolling students in courses.
This file describes **what** the system does. `AGENTS.md` describes **how** the code is written.

## Entities

### Student
- `Id` (Guid), generated by the server.
- `FullName`: required, at most 120 characters, stored trimmed.

### Course
- `Id` (Guid), generated by the server.
- `Title`: required, at most 120 characters, stored trimmed.
- `Capacity`: number of seats, must be greater than 0. Default is 30.
- `EnrolledCount`: number of students currently enrolled. Maintained by the system, never set by the client.
- `RowVersion` (Guid): concurrency token, changes every time the course changes.

### Enrollment
- Links one student to one course. The pair (`StudentId`, `CourseId`) is unique.
- `EnrolledAt`: UTC time set by the server when the enrollment is created.

## Business Rules

### Enrolling a student
1. The student must exist, otherwise `Students.NotFound` (404).
2. The course must exist, otherwise `Courses.NotFound` (404).
3. A student cannot enroll in the same course twice: `Enrollments.AlreadyEnrolled` (409).
   This also holds when two identical requests arrive at the same time.
4. A course cannot have more enrollments than its capacity: `Enrollments.CourseFull` (409).
5. A successful enrollment increases the course's `EnrolledCount` by 1.
6. If the course changed during the request (another enrollment or cancellation at the same time), the request fails with `Enrollments.ConcurrencyConflict` (409) and the client should retry. Seats are never over-booked.

### Canceling an enrollment
1. The enrollment must exist, otherwise `Enrollments.NotFound` (404).
2. Canceling removes the enrollment and frees the seat (`EnrolledCount` decreases by 1).
3. Concurrent changes to the same course return `Enrollments.ConcurrencyConflict` (409).

### Lists
- Every list is paginated: `page` starts at 1 (default 1), `pageSize` is between 1 and 100 (default 20).
- A page past the end returns an empty `items` list with the correct `totalCount`.
- Fixed order (no client sorting or filtering yet):
  - Students: by full name, then by ID.
  - Courses: by title, then by ID.
  - A student's courses: by course title, then by course ID.

### Validation
- Invalid input returns 400 with code `Validation.Failed` and the errors grouped by field.
- IDs must not be an empty Guid.

## Endpoints

All error responses are `ProblemDetails` with `code` and `correlationId`. Every response has an `X-Correlation-Id` header.

### API versions
- The API version is part of the URL: `/api/v{version}/...`. Every endpoint below exists in **v1**.
- **v2** exists only for courses: all course endpoints are available under `/api/v2/courses`, and `GET /api/v2/courses/{id}` returns a different shape (see Courses).
- Courses **v1 is deprecated**: course responses carry `api-deprecated-versions: 1.0`. Clients should move to v2.
- Every versioned response lists the active versions of that resource in `api-supported-versions` and the deprecated ones in `api-deprecated-versions`. A deprecated version is not repeated in `api-supported-versions` (courses: `api-supported-versions: 2.0`, `api-deprecated-versions: 1.0`).
- A version that does not exist for a resource (e.g. `/api/v3/courses`, `/api/v2/students`), or a URL without a version (`/api/courses`), returns **404** with a `ProblemDetails` body (no route exists for it), and the request does not reach any handler.
- The v2 course response is a demonstration of versioning. In practice an additive change like a new field does not require a new version; a new version is for breaking changes (removed or renamed fields, changed types or meaning).

### Idempotency
- Every `POST` endpoint requires an `Idempotency-Key` header (a unique value per operation, e.g. a UUID; max 100 visible ASCII characters).
  - Missing → 400 `Idempotency.KeyMissing`; malformed → 400 `Idempotency.KeyInvalid`.
- Sending the same request again with the same key does **not** run it again: the first response is returned (same status, body and `Location`) with the header `Idempotency-Replayed: true`. This makes retries after a timeout or a lost connection safe (no duplicate student, course, enrollment or post).
- The same key with a different request (another endpoint, version or body) → 422 `Idempotency.KeyReused`.
- The same key while the first request is still running → 409 `Idempotency.RequestInProgress`.
- Responses below 500 are stored, including business errors (e.g. a replayed `Enrollments.AlreadyEnrolled` stays 409). After a 5xx the key can be retried.
- A key and its response are kept for 24 hours; after that the key can be used again.
### Students
- `POST /api/v1/students` — create a student. Body: `{ "fullName" }`. Returns 201 with the new ID.
- `GET /api/v1/students/{id}` — get a student. Returns 200, or 404.
- `GET /api/v1/students?page=&pageSize=` — list students. Returns 200 with a paged result.

### Courses
- `POST /api/v1/courses` — create a course. Body: `{ "title", "capacity" }` (`capacity` optional, default 30). Returns 201 with the new ID.
- `GET /api/v1/courses/{id}` — get a course (**v1, deprecated**), including `capacity`, `enrolledCount` and `rowVersion`. Returns 200, or 404.
- `GET /api/v2/courses/{id}` — get a course (**v2**): the v1 fields plus `availableSeats` (= `capacity` − `enrolledCount`). Returns 200, or 404. `POST` and the list are the same in v2 under `/api/v2/courses`.
- `GET /api/v1/courses?page=&pageSize=` — list courses. Returns 200 with a paged result.

### Enrollments
- `POST /api/v1/students/{studentId}/enrollments` — enroll a student. Body: `{ "courseId" }`. Returns 204, 404, or 409.
- `GET /api/v1/students/{studentId}/enrollments/{courseId}` — get an enrollment. Returns 200, or 404.
- `DELETE /api/v1/students/{studentId}/enrollments/{courseId}` — cancel an enrollment and free the seat. Returns 204, 404, or 409.
- `GET /api/v1/students/{studentId}/courses?page=&pageSize=` — list the courses a student is enrolled in. Returns 200, or 404 if the student does not exist.

### External API (JSONPlaceholder)
A reference example of calling an external API. These endpoints are served by `JsonPlaceholderController` under `/api/v1/jsonplaceholder`, proxy https://jsonplaceholder.typicode.com, and do not touch the database.
- `GET /api/v1/jsonplaceholder/users?page=&pageSize=` — list external users (paging is done by the external API with `_page`/`_limit`; `totalCount` comes from its `X-Total-Count` header). Returns 200, 400, 502, or 504.
- `GET /api/v1/jsonplaceholder/users/{id}` — get one external user. `id` must be greater than 0. Returns 200, 400, 404 (`JsonPlaceholder.UserNotFound`), 502, or 504.
- `POST /api/v1/jsonplaceholder/posts` — create a post. Body: `{ "userId", "title", "body" }`; `userId` > 0, `title` required (max 200), `body` required (max 2000). Returns 201 with the created post, 400, 502, or 504. JSONPlaceholder does **not** persist it and always returns `id = 101`.

External failures:
- The external API is slow (no response within the configured timeout) → 504 `ExternalService.Timeout`.
- The external API cannot be reached or returns an unexpected error → 502 `ExternalService.Unavailable`.
- The external API returns invalid JSON or an incomplete response → 502 `ExternalService.InvalidResponse`.
- No automatic retries.

### System
- `GET /health` — health check, including a database check (the external API is not part of it).
- `GET /scalar` — interactive API documentation (Scalar) to try every endpoint. Development only.
- `GET /openapi/v1.json` — OpenAPI document used by Scalar. Development only.

## Project Notes
Technical facts specific to this project. `AGENTS.md` is generic and refers to these through placeholders.
- Architecture: Clean Architecture + CQRS + Repository Pattern with Unit of Work, plus API best practices: API versioning (Asp.Versioning 10.2.1, URL segment) and idempotency (`Idempotency-Key` on every POST, stored in the `IdempotencyRecords` table). Rate limiting and caching are planned.
- `[Project]` = `School`: `SchoolDbContext`, `SchoolSeed`, `SchoolUnitOfWork`.
- Database provider: SQLite, connection string `School` = `Data Source=school.db;Foreign Keys=True` (file created next to the WebAPI project). `SchoolUnitOfWork` maps SQLite extended error codes `1555` (primary key) and `2067` (unique) to `PersistenceErrors.DuplicateKey`.
- Solution file: `CleanArchitectureTemplate_CQRS_RepositoryPattern_APIsBestPractices.slnx`.
- EF Core CLI: local tool in `dotnet-tools.json` (dotnet-ef 11.0.0). Run `dotnet tool restore` once after cloning.
- External service `[Service]` = `JsonPlaceholder`: `IJsonPlaceholderClient`, `JsonPlaceholderClient`, settings `ExternalServices:JsonPlaceholder:BaseUrl` = `https://jsonplaceholder.typicode.com/`. Shared timeout for all external services: `ExternalServices:TimeoutSeconds` = 10.
- Known exception: migration `20261120061000_InitialSchool` was written by hand and has no `.Designer.cs` file. Do not copy that style; create new migrations with the EF Core CLI.
- EF Core sensitive data logging is **enabled in all environments** (`Database:EnableSensitiveDataLogging = true` in `appsettings.json`), by the project owner's decision. Log files therefore contain SQL parameter values such as student names. To disable it in one environment, set it to `false` in `appsettings.{Environment}.json`.
